# 스펙 초안 — 레퍼런스 자막 효과 분석 · 캡컷 재연 기능

- 상태: **초안 v0.1** (2026-08-25)
- 기반 저장소: `claude-video` (`/watch` 스킬 — 영상 분석 파이프라인)
- 작성 목적: 기존 `/watch`(분석)에 "캡컷 적용(출력)" 절반을 붙이기 위한 요구사항 정리

---

## 1. 배경과 목표

지금의 `/watch`는 레퍼런스 영상을 **보는 것**까지만 한다(프레임 추출 + 트랜스크립트).
이 스펙의 목표는 그 분석 결과를 **캡컷에서 재사용 가능한 형태로 출력**하는 것이다.

> **한 줄 목표:** 레퍼런스 영상을 넣으면, 그 영상의 자막 효과·효과음을 추정해
> 캡컷 프로젝트(드래프트)로 만들어 주고, 사용자는 **텍스트만 바꾸면** 같은
> 효과·효과음이 그대로 적용된 결과물을 얻는다.

### 성공 기준 (Definition of Done)

1. 레퍼런스 영상 1개를 입력하면, 자막 구간별로 "추정 캡컷 효과 이름 + 신뢰도"가 나온다.
2. 생성된 캡컷 드래프트를 캡컷에서 열었을 때 오류 없이 로드되고, 자막 효과(등장/퇴장 애니메이션·스타일)가 레퍼런스와 유사하게 재생된다.
3. 드래프트 안의 자막 **텍스트만 교체**해도 효과가 깨지지 않는다 (효과는 세그먼트에, 텍스트는 머티리얼에 분리 저장).
4. 화면 전환 시점의 효과음(우쉬, 팝 등)이 타임라인의 같은 상대 위치에 오디오 클립으로 배치된다.

---

## 2. 용어

| 용어 | 정의 |
|---|---|
| 레퍼런스 | 따라 만들고 싶은 원본 영상 (URL 또는 로컬 파일) |
| 자막 효과 | 자막의 스타일(폰트·색·외곽선·배경) + 애니메이션(등장/유지/퇴장) 조합 |
| 캡컷 드래프트 | 캡컷 프로젝트 파일. 핵심은 `draft_content.json` (트랙·세그먼트·머티리얼 구조) |
| 효과 매핑 테이블 | "관찰된 효과 특징 → 캡컷 내장 효과 ID" 대응표 (큐레이션 자산) |
| 오디오 이벤트 | 배경음악·음성이 아닌 짧은 효과음 (전환음, 강조음 등) |

## 3. 사용자 시나리오

```
사용자: /replicate https://youtu.be/xxxx
  → ① 분석 리포트: 자막 구간 7개, 효과 추정 (예: "타자기 등장 + 흔들림 강조", 신뢰도 高/中/低)
  → ② 오디오 이벤트 4개 검출 (0:03 전환음, 0:11 팝음 …)
  → ③ 캡컷 드래프트 생성: ~/Movies/CapCut/.../새 프로젝트
사용자: 캡컷에서 프로젝트 열기 → 자막 더블클릭 → 내 문구로 교체 → 완성
```

교체 편의를 위해 자막 텍스트는 플레이스홀더(`[자막1] 원문: "..."`)로 넣는다.
선택 입력: 사용자가 바꿔 넣을 문구 목록을 미리 주면 처음부터 그 텍스트로 생성.

## 4. 기능 요구사항

### F1. 레퍼런스 자막 효과 분석 (기존 `/watch` 확장)

- **F1-1 자막 구간 검출**: 트랜스크립트 타임스탬프 + 프레임에서 자막 영역 관찰로
  "자막이 뜨는 구간" 목록을 만든다 (시작·끝·텍스트 내용).
- **F1-2 효과 관찰용 고밀도 샘플링**: 자막의 등장/퇴장 **전후 0.5초**를 고 fps(최대 2fps 제한 해제, 예: 10fps)로 추출하는 신규 모드가 필요하다.
  현재 `frames.py`의 2fps 캡으로는 애니메이션 프레임을 못 잡는다.
- **F1-3 효과 특징 기술**: 각 자막 구간에 대해 Claude가 프레임 시퀀스를 보고
  구조화된 특징을 산출한다:
  - 등장 방식 (페이드 / 슬라이드 방향 / 타자기 / 팝 / 줌 …)
  - 유지 중 효과 (흔들림 / 무지개 / 글로우 / 없음)
  - 퇴장 방식
  - 스타일 (대략적 폰트 계열, 색, 외곽선/그림자/배경 박스 유무, 화면 내 위치)

### F2. 캡컷 효과 매핑

- **F2-1 매핑 테이블**: F1-3의 특징 → 캡컷 내장 텍스트 애니메이션/효과 ID 대응표.
  JSON/YAML 정적 자산으로 저장소에 큐레이션한다 (`assets/capcut-effect-map.json`).
  초기 버전은 **한국 쇼츠에서 많이 쓰는 효과 상위 N개(예: 20개)** 를 수동 등록.
- **F2-2 신뢰도와 폴백**: 매핑마다 신뢰도(高/中/低)를 붙인다. 매핑 실패 시
  "가장 비슷한 효과 + 수동 확인 필요" 로 표기하고 드래프트에는 기본 효과로 넣는다.
  절대 조용히 아무 효과나 확정하지 않는다.
- **F2-3 효과 ID 수집 방법**: 캡컷은 효과 ID를 공개 문서화하지 않으므로,
  캡컷에서 효과를 하나씩 적용한 샘플 드래프트를 만들어 `draft_content.json`을
  역추출하는 방식으로 ID를 수집한다 (부트스트랩 작업, 마일스톤 M2).

### F3. 캡컷 드래프트 생성

- **F3-1 생성 방식**: `draft_content.json` 직접 생성. 구현 후보는
  [pyJianYingDraft](https://github.com/GuanYixuan/pyJianYingDraft) (캡컷/剪映 드래프트 생성 라이브러리) 활용 또는 자체 최소 구현.
  → **미결 D-1**: 라이브러리 채택 여부 (라이선스·캡컷 국제판 호환성 검증 필요).
- **F3-2 텍스트-효과 분리**: 자막 텍스트는 텍스트 머티리얼에, 효과는 세그먼트의
  애니메이션 참조에 넣어, 캡컷 UI에서 텍스트를 수정해도 효과가 유지되게 한다.
  (이것이 "텍스트만 바꾸면 효과 적용"의 구현 근거)
- **F3-3 타임라인 재현**: 레퍼런스의 자막 구간 타이밍을 상대 시간 그대로 배치.
  영상 본체 트랙은 비워 두거나 플레이스홀더 클립(검정 배경)을 넣는다.
- **F3-4 대상 버전**: 캡컷 데스크톱 국제판 기준. 버전 명시(예: 3.x)하고,
  드래프트 스키마가 버전에 민감하므로 검증한 버전을 README에 못 박는다.

### F4. 효과음 검출·재연

- **F4-1 오디오 이벤트 검출**: 오디오 트랙에서 onset(급격한 에너지 변화) 검출로
  짧은 효과음 후보를 찾는다. ffmpeg 필터 또는 stdlib 기반 에너지 분석
  (저장소의 "pure-stdlib" 원칙 유지 여부 → **미결 D-2**: librosa 등 의존성 허용?).
- **F4-2 화면 전환과의 상관**: 이미 있는 장면 전환 검출(ffmpeg scene-change)과
  시각을 대조해 "전환 효과음"을 식별한다 (전환 ±0.3초 내 onset = 전환음).
- **F4-3 재연 방식 2단계**:
  1. **1차(기본): 원본에서 클립 추출** — 검출 구간의 오디오를 잘라 wav로 저장하고 드래프트의 오디오 트랙에 배치. 확실히 "같은 소리"가 난다.
  2. **2차(개선): 라이브러리 매칭** — 캡컷 내장 효과음 또는 무료 SFX와 매칭해 원본 오디오 없이 재연. (M4 이후 과제)
- **F4-4 저작권 주의**: 원본 클립 추출 방식은 개인 학습·프로토타입 용도로 한정하고, 산출 리포트에 저작권 주의 문구를 포함한다.

## 5. 비기능 요구사항

- 기존 `/watch`의 설치 경험 유지: 신규 무거운 의존성(딥러닝 오디오 모델 등)은 기본 경로에 넣지 않는다.
- 분석~드래프트 생성까지 1분 내외 (60초 쇼츠 기준, 다운로드 제외).
- 실패는 명시적으로: 매핑 불가·스키마 불일치 시 어떤 항목이 왜 실패했는지 리포트.

## 6. 범위 제외 (v1에서 안 하는 것)

- 영상 본체 편집 재연 (컷 편집, 화면 효과, 색보정)
- 배경음악 식별·교체
- 캡컷 모바일 앱, 剪映(중국판) 지원
- 효과 "완벽 일치" 보장 — v1은 "충분히 비슷한 효과 + 수동 미세조정" 수준

| M4 | 오디오 이벤트 검출 + 원본 클립 추출 배치 | 효과음 포함 드래프트 | 🔶 분석 절반 구현 — `audio_events.py` (F4-1 onset 검출, F4-2 장면 상관, F4-3 1차 클립 추출, F4-4 고지). 드래프트 배치는 M3 검증 뒤 |

**M3의 리스크가 가장 크다** (드래프트 스키마 비공개·버전 민감). M1과 병행으로 M3의 스파이크(효과 1개 하드코딩 드래프트를 캡컷이 여는지)를 먼저 검증할 것을 권장.

## 8. 미결 사항

- **D-1**: pyJianYingDraft 채택 vs 자체 구현 (국제판 캡컷 호환·라이선스 확인)
- **D-2**: ~~오디오 분석 의존성 허용 범위~~ → **확정(2026-08-26): stdlib + ffmpeg 고수.** `audio_events.py`가 ffmpeg PCM 디코드 + 1차 차분(고주파) 에너지 novelty 비율로 onset을 검출한다. v1 휴리스틱으로 충분치 않으면 그때 재검토.
- **D-3**: 캡컷 대상 버전 확정 (사용자 실제 사용 버전 기준)
- **D-4**: 명령 형태 — `/watch`의 플래그(`--replicate`)로 붙일지, 별도 스킬(`/replicate`)로 분리할지. 업스트림(bradautomates)과 구조가 갈라지므로 **별도 스킬 분리 권장**.
